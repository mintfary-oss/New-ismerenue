## 1. Обзор системы

AQI Platform — программный комплекс мониторинга качества атмосферного воздуха города **Кемерово**. Разработан в соответствии с ТЗ государственного контракта №М05-00285-26-ЭА.

### Что делает система

| Функция | Описание |
|---------|----------|
| Сбор данных | Принимает измерения с 4 физических датчиков (NO₂, O₃, CO, H₂S, SO₂, PM2.5) |
| Расчёт AQI | Вычисляет индекс качества воздуха по методологии US EPA |
| Прогноз | Прогнозирует AQI на 6 часов (алгоритм EWMA + IDW) |
| Архив | Хранит данные 60 месяцев с автоматическим удалением устаревших |
| Отчёты | Генерирует CSV/XLSX отчёты по произвольным периодам |
| Виджет | Предоставляет публичный iframe для городского сайта |
| API | REST API с JWT-авторизацией для интеграций |

### Ключевые характеристики (по ТЗ)

| Параметр | Значение |
|----------|----------|
| Число точек мониторинга | 4 (Кемерово) |
| Хранение данных | 60 месяцев |
| Прогноз | 6 часов вперёд |
| Обновление прогноза | каждые 20 минут |
| Браузеры | Chrome, Firefox, Safari, Edge (последние 2 версии) |
| Мобильные устройства | iOS Safari, Android Chrome |
| Развёртывание | Docker, автономно без облака |
| Установка | одна команда `./scripts/install.sh` |

### Компоненты

**Go API Server** — основной бэкенд:
- Chi v5 router
- Middleware: JWT auth, RBAC, security headers (OWASP), rate limiting
- Graceful shutdown (SIGTERM/SIGINT)
- Compiled into single 2.5 MB binary

**React SPA** — веб-интерфейс:
- Vite + React 18 + TypeScript
- Страницы: Dashboard, Map, Admin, Инструкция
- Код разделён на чанки для быстрой загрузки

**PostgreSQL + TimescaleDB** — основная СУБД:
- TimescaleDB hypertables для временных рядов
- Retention policy (удаление данных > 60 месяцев)
- 9 таблиц, 5 миграций

**Redis** — кэш и блеклист:
- Инвалидация JWT токенов при logout
- Rate limiting (защита от брутфорса)
- Блокировка аккаунтов при множественных неверных паролях

**Nginx** — точка входа:
- TLS termination
- Раздача React SPA статики
- Proxy на Go API
- Gzip сжатие

## 5. База данных

### Схема (9 таблиц)

```sql
-- Пользователи
users (id UUID PK, email UNIQUE, username, password_hash, role, is_active, created_at)

-- Датчики качества воздуха
sensors (id UUID PK, name, address, lat, lng, type, is_active, last_seen, created_at)

-- Измерения (TimescaleDB hypertable, партиционирована по time)
measurements (
  time TIMESTAMPTZ NOT NULL,       -- время измерения
  sensor_id UUID FK,               -- датчик
  no2, o3, co, h2s, so2, pm25     -- концентрации (мг/м³)
  temperature, humidity, pressure, wind_speed, wind_dir  -- метео
)

-- Прогнозы
forecasts (
  time TIMESTAMPTZ NOT NULL,
  point_id TEXT,                   -- ID контрольной точки Кемерово
  horizon_hours INT,               -- 0, 1, 2, 3, 6
  aqi INT, aqi_category TEXT,
  pm25_forecast, no2_forecast, so2_forecast FLOAT,
  model_version TEXT,              -- "v2-ewma-idw"
  created_at TIMESTAMPTZ,
  UNIQUE (time, point_id, horizon_hours)
)

-- API токены датчиков
api_tokens (id UUID PK, user_id UUID FK, name, token_hash, prefix, is_active, created_at, last_used_at)

-- Обратная связь
feedback (id UUID PK, user_id UUID FK, subject, message, created_at)

-- Отчёты
reports (id UUID PK, name, type, format, period_from, period_to, status, file_data BYTEA, row_count, created_by UUID FK, created_at)

-- Сброс пароля
password_resets (id UUID PK, user_id UUID FK, token_hash, expires_at, used_at, created_at)

-- Логи входа (для аудита)
login_attempts (email, ip, success, created_at)
```

### TimescaleDB оптимизации

```sql
-- Гипертаблица measurements — автоматическое партиционирование по времени (7-дневные чанки)
SELECT create_hypertable('measurements', 'time', chunk_time_interval => INTERVAL '7 days');

-- Retention policy — автоудаление данных старше 60 месяцев (5 лет)
SELECT add_retention_policy('measurements', INTERVAL '60 months');

-- Индексы для быстрых запросов
CREATE INDEX ON measurements (sensor_id, time DESC);
CREATE INDEX ON forecasts (point_id, horizon_hours, time DESC);
```

### Резервное копирование

```bash
# Бэкап (рекомендуется cron каждые 6 часов):
pg_dump -h localhost -U aqi_user aqi_db | gzip > /backups/aqi_$(date +%Y%m%d_%H%M).sql.gz

# Восстановление:
gunzip < /backups/aqi_20260801_1200.sql.gz | psql -h localhost -U aqi_user aqi_db
```

## 7. Аутентификация и безопасность

### JWT токены

| Параметр | Значение |
|----------|----------|
| Алгоритм | HS256 |
| Access token TTL | 15 минут |
| Refresh token TTL | 30 дней |
| Инвалидация | Redis blacklist при logout |

### Хэширование паролей

Используется **Argon2id** (рекомендация OWASP 2025):
- memory: 64 МБ
- iterations: 3
- parallelism: 4
- salt length: 32 байта
- hash length: 32 байта

### Защита от атак

| Угроза | Защита |
|--------|--------|
| Brute force | Блокировка аккаунта после 5 неверных попыток |
| XSS | Content-Security-Policy headers |
| Clickjacking | X-Frame-Options: DENY (кроме /widget/) |
| CSRF | SameSite cookies + CORS |
| Path traversal | Валидация входных данных |
| SQL injection | Параметризованные запросы pgx |
| JWT forgery | Подпись HS256, blacklist инвалидированных токенов |
| Rate limiting | 100 req/min на /api/v1/auth/login |

### RBAC (Роли и права)

| Ресурс | Viewer | Analyst | Admin |

| Просмотр измерений | ✅ | ✅ | ✅ |

| Загрузка данных | — | ✅ | ✅ |
| Генерация отчётов | — | ✅ | ✅ |
| Управление датчиками | — | — | ✅ |
| Управление пользователями | — | — | ✅ |

## 8. Прогнозный движок

### Алгоритм (двухэтапный)

#### Этап 1: EWMA (Exponentially Weighted Moving Average)

Сглаживает шумовые выбросы датчика и экстраполирует тренд:

```
S_t = α × X_t + (1 − α) × S_{t−1}
```

Параметры: α = 0.3 (оптимально для часовых рядов), окно 6 часов.

**Что вычисляется:**
- Сглаженное текущее значение PM2.5 и NO₂
- Почасовой тренд Δ (рост/падение концентрации)

#### Этап 2: IDW (Inverse Distance Weighting)

Интерполирует значения с датчиков на 4 контрольные точки:

```
V_p = Σ(w_i × V_i) / Σ(w_i),   где w_i = 1 / d_i^p
```

Параметры: p = 2 (стандарт), расстояния по формуле Haversine.

#### Горизонты прогноза

| Horizon | Описание |
|---------|----------|
| 0 ч | Текущее (с коррекцией EWMA) |
| 1 ч | +1 час |
| 2 ч | +2 часа |
| 3 ч | +3 часа |
| 6 ч | +6 часов |

### 4 точки мониторинга Кемерово

| ID | Название | Координаты | Район |
|----|---------|------------|-------|
| `center` | Площадь Советов | 55.3558, 86.0869 | Центральный |
| `kirovsky` | Кировский р-н | 55.3337, 86.1059 | Кировский |
| `rudnichniy` | Рудничный р-н | 55.4128, 86.0394 | Рудничный |
| `zavodskoy` | Заводской р-н | 55.3392, 86.1592 | Заводской |

### Расчёт AQI (US EPA методология)

```
AQI = ((AQI_Hi − AQI_Lo) / (C_Hi − C_Lo)) × (C − C_Lo) + AQI_Lo
```

| AQI | Категория | Цвет | Описание |
|-----|-----------|------|----------|
| 0–50 | Good | 🟢 | Хорошее |
| 51–100 | Moderate | 🟡 | Умеренное |
| 101–150 | Unhealthy (sensitive) | 🟠 | Нездоровое для чувствительных групп |
| 151–200 | Unhealthy | 🔴 | Нездоровое |
| 201–300 | Very Unhealthy | 🟣 | Очень нездоровое |
| 301+ | Hazardous | ⚫ | Опасное |

## 9. IMAP-приёмник данных

Система автоматически опрашивает почтовый ящик для получения данных от датчиков.

### Как это работает

1. Планировщик запускает polling каждые **5 минут**
2. Подключается к IMAP серверу (configurable, по умолчанию Yandex Mail)
3. Читает непрочитанные письма от датчиков
4. Извлекает вложения: `.csv` или `.xlsx`
5. Парсит данные (поля: sensor_id, time, no2, o3, co, h2s, so2, pm25, ...)
6. Вызывает `MeasurementService.IngestBatch`
7. Помечает письма как прочитанные

### Формат CSV файла от датчика

```csv
sensor_id,time,no2,o3,co,pm25,temperature,humidity
uuid-1234,2026-08-01T10:00:00Z,0.04,0.02,0.5,0.012,22.5,65
uuid-1234,2026-08-01T10:01:00Z,0.041,0.021,0.48,0.013,22.6,64
```

### Конфигурация

```yaml
email:
  imap_server: imap.yandex.ru:993
  imap_user: ecology@kemerovo.ru
  imap_password: ${EMAIL_IMAP_PASSWORD}
  poll_interval: 5m
```

```sql
-- Размер данных в таблице измерений
SELECT
  chunk_schema, chunk_name,
  pg_size_pretty(pg_total_relation_size(format('%I.%I', chunk_schema, chunk_name))) as size,
  range_start, range_end
FROM timescaledb_information.chunks
ORDER BY range_start DESC
LIMIT 20;

-- Количество измерений за последние 24 часа
SELECT COUNT(*) FROM measurements WHERE time > NOW() - INTERVAL '24 hours';

-- Активные датчики
```
